## 查看服务日志

```bash
systemctl status yali
journalctl -u yali -n 100 --no-pager
```

第一条看进程是否在运行，第二条看最近 100 行日志。日志里没有报错只说明进程没崩，不说明提醒发出去了。

## 重启服务

```bash
sudo systemctl restart yali
sudo systemctl reload caddy
```

只改了后端代码时执行第一条；改了反向代理配置才需要第二条。

## 备份数据库

```bash
sqlite3 /srv/yali/data/yali.db ".backup '/srv/yali/backup/yali-<日期>.db'"
```

用 `.backup` 而不是直接拷文件，是因为服务运行时直接拷贝可能拷到写了一半的状态。备份能生成不等于能恢复，恢复演练在对话里没有记录。

## 指令写法纠偏

| 原来的问题 | 为什么会被误解 | 更好的写法方向 |
| --- | --- | --- |
| 只说“弄好看点” | AI 不知道要改哪里、改到什么程度 | 说明对象、要保留的东西、要变的东西 |
| 没说不能动什么 | AI 顺手改了无关的页面 | 写明禁区，要求列出改动的文件 |
| 一次提了四五件事 | 漏项，出问题也分不清是哪一步引入的 | 一次一件，验证后再提下一件 |

## 真实纠偏案例：从“弄好看点”到可验收的要求

原说法：

> 把首页弄好看点，现在太乱了。

AI 把整个首页重排了一遍，连记录按钮的位置都变了。

改进后：

```text
只调整首页的植物卡片：
1. 卡片之间的间距统一为 12px，卡片内上下留白 16px。
2. 植物名用 16px 加粗，下次浇水时间用 13px 灰色。
3. 不改卡片的排列顺序，不动底部的记录按钮。
改完后列出修改了哪些文件。
```

第二次的结果只动了卡片样式，一次通过。

## 可复用的指令骨架

下面是根据几次纠偏整理出的模板，不是某次对话的原文：

```text
目标：<这次只做的一件事>
范围：<允许修改的文件或组件>
不要动：<明确的禁区>
完成标准：<怎么算做完，怎么验证>
改完后：列出修改的文件和每处改了什么
```

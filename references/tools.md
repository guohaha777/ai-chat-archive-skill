# 命令、文件和报错

脚本只做确定性的事：解析、筛选、按线索打分排序、逐字抽取、核对、统计。打分只决定先给模型看什么，不判断对错；任何一段原文都能用 `show` 打开。全部只依赖 Python 标准库，需要 Python 3.9 或更高版本。

## 命令

都在 skill 目录下执行，形如 `python3 scripts/kb.py <命令> ...`。

| 命令 | 作用 |
| --- | --- |
| `start <导出目录> <工作区>` | 解析导出，只留一问一答，生成会话目录 `catalog.md` |
| `topics <工作区>` | 检查 `topics.json`，写出 `话题目录.md` |
| `digest <工作区> [--topic 话题] [--budget 字数]` | 给选中的话题挑精选、抽原文资产；可只重做一个话题 |
| `show <工作区> <话题> u12 u30-u33` | 打印这些单元的全文，默认每个最多 6000 字，`--max-chars` 可调 |
| `find <工作区> <关键词> [--topic 话题] [-n 20]` | 关键词出现在哪些单元，各带一小段上下文 |
| `verify <工作区> <知识库>` | 检查成品、扫描敏感信息、保存清单 |
| `hub <知识库>` | 从各话题页面汇总术语、命令、AI 指令，生成 `00_跨话题汇总/` 并在入口页加一节 |
| `gaps <工作区> <知识库> [--topic 话题]` | 写出 `省略报告.md`：没选入的轮次分档统计，以及成品里缺的高频术语和命令 |
| `more <工作区> [--tier high\|all] [--topic 话题] [--keyword 词] [--budget 字数]` | 从没选入的轮次里再取一份，写成 `digest/<话题>/补充N.md` |

`start` 可以对新的导出再运行一次，会建新快照并保留旧会话的编号；之后再运行 `digest`。`digest` 每次都重写它处理的话题的三份文件，不动已经写好的页面。

## digest 怎么挑

一轮问答（一次提问加随后的回答）是打分的单位。每轮按八类可复用内容分别计分，每类看三样：本人的提问像不像在要这类东西、回答里有没有交付这类东西的说法、回答的形状。形状不依赖领域词汇，所以视觉、文学、心理、技术的对话都适用。

| 类 | 提问里的线索 | 回答里的线索 | 形状 |
| --- | --- | --- | --- |
| `term` 术语与概念 | 什么是、什么意思、叫什么、专业说法、区别、怎么描述 | 是指、全称、又称、称为、可以理解为、英文是 | 两个以上“中文（English）”；三行以上“**词**：解释”；术语表 |
| `code` 可复用的代码与命令 | 怎么运行／启动／部署／上传、命令、配置文件 | 运行、终端、安装、环境变量 | 命令代码块（bash、sql，或以 git、npm、docker 等开头）；短的配置代码块 |
| `method` 方法与流程 | 流程、步骤、怎么推进、从哪开始、模板、清单 | 第几步、阶段、工作流、清单、规范、约定、验收标准 | 三条以上连续的编号步骤；流程图 |
| `prompt` 给 AI 的指令 | 提示词、怎么跟 Cursor 说 | 提示词、发给、只读、不要修改 | 像指令的纯文本代码块；本人发出的长指令 |
| `decision` 决策与取舍 | 选哪个、要不要、值不值得 | 决定、最终方案、放弃、代价、优缺点、更适合 | |
| `issue` 问题与排查 | 报错、不行、为什么不 | 根因、原因是、解决方法、验证、日志、error、404 | |
| `lesson` 经验与复盘 | 复盘、总结一下、下次 | 经验、教训、踩坑、务必、关键是、总结 | |
| `reflect` 个人判断与反思 | 我发现、我担心、内耗、我的方向 | 模式、假设、证据、反例、盲区 | |

另外加分：本人在纠正 AI（不对、还是不行、我的意思是）；每段会话的第一轮（目标）和最后一轮（结果）。同一个线索词重复出现不重复计分。

总分是各类得分乘以权重之和。选的时候分三步：先让每段有线索的会话选入自己最好的一轮，从最强的会话开始，合计不超过预算的四分之一；再按权重给每一类分一份预算（合计六成），各取自己最好的；剩下的不分类别，按总分补齐。这样字数最多的那类（通常是排查）不会挤掉其他类。

### focus.json：按这个人的关注点调整

放在工作区根目录，可选。没有它就用默认权重。

```json
{
  "weights": {"term": 4, "method": 4, "issue": 1, "reflect": 0},
  "keywords": {"term": ["折纸", "构图", "拟物化"], "any": ["芽历"]},
  "topics": {"摄影入门": ["光圈", "快门", "景深"], "芽历": ["浇水提醒", "同步"]},
  "lexicon": ["折纸", "折痕", "留白"]
}
```

- `weights`：只写要改的类。0 表示不要这类。
- `keywords`：某一类下的词命中时给那一类加分；`any` 下的词命中时直接加总分。写用户明确说关心的领域词。
- `lexicon`：这个人的领域里值得进术语候选的词。脚本内置了一份常见界面和前端交互词（hover、tooltip、modal、toast、轮播、弹窗、悬停等），原文里出现八次以上、分布在两段以上会话时，即使没人问过也进候选；你的领域词（工艺、设计、写作用语）靠这一项补。
- `topics`：只在这个话题里生效的关键词，命中时加总分。由模型在归话题时写，每个话题 5 到 10 个：项目名、领域词、反复出现的工具和对象。通用线索认不出一个话题自己的词汇，这一项补的就是它。

改完重新运行 `digest`。

### 其余规则

| 线索 | 例子 |
| --- | --- |
| 说了原因 | 根因、原因是、问题出在 |
| 给了处理或决定 | 解决方法、改成、决定、最终方案、放弃 |
| 有验证或经验 | 验证、已经正常、经验、教训、注意、踩坑 |
| 有报错 | 报错、error、failed、404、502 |
| 有可执行的命令 | bash、sql 等代码块，或以 git、docker、npm 等开头的行 |
| 本人在纠正 AI | 不对、还是不行、没有生效、我的意思是 |
| 位置 | 每段会话的第一轮（目标）和最后一轮（结果） |

每轮按“得分除以篇幅的平方根”排序，装满预算为止。默认预算是话题原文的一成，最少 6000 字；到 45000 字后增长放慢，最多 60000 字。选入的回答会缩成骨架：标题、带线索的段落、短命令保留，长代码只留开头，中间用 `〔…〕` 标出。没选入的轮次留一行提问开头，没选入的会话留一行标题，所以不会有内容完全看不见。

`原文资产.md` 依次是：术语候选（来自“中文（English）”写法、被加粗解释的词、表格里的术语、本人问过“什么是 X”的词；要有两条以上证据才列入：问过、原文有解释、中英对照、被加粗或列表解释、在两段以上会话出现、本身是外文专名；两三个字的普通词还要“问过并且有解释”；带提及次数、会话数和原文里的一句解释）、流程候选（成段的编号步骤，带所在标题和开头几步）、命令、给 AI 的指令、报错、代码里的名字。前两项有噪声，是给模型挑的清单，不是结论。

命令按第一条命令的工具名分组，标出重复次数和它前面那句话；给 AI 的指令来自两处：回答里的纯文本代码块（前文提到“指令”“发给 Cursor”之类，或内容像指令），以及本人发出的长指令。

精选偏薄、漏了某件事时，先用 `find` 找，再决定要不要加大 `--budget` 重做。

## hub：跨话题汇总

`hub` 只读成品页面，不读工作区，所以对任何按本 skill 版式写的库都能运行，也可以反复运行：每次都整个重建 `00_跨话题汇总/`，并替换入口页里的“跨话题汇总”一节（没有就插在第一个二级标题之前）。

| 收什么 | 怎么认 |
| --- | --- |
| 术语 | 表头第一列是“术语”“概念”“名词”“词汇”“风格”“叫法”的表格，每行一条：第一列是词，第二列是含义 |
| 命令 | 语言是 `bash`、`sh`、`sql` 等的代码块，或大半行以 git、npm、docker 等开头的代码块；说明取代码块前面那一句 |
| AI 指令 | `text` 或不标语言的代码块，且所在小节标题或前一句提到“指令”“提示词”“prompt”，或内容本身像指令 |

同一个词出现在两个以上话题时（“RLS（Row Level Security）”和“RLS”算同一个），在术语总览最前面并排列出各话题的含义。完全相同的命令只列一次，出处写全。命令按第一条非 `cd` 命令的工具分组。

`verify` 对汇总页只查链接和结构，不查篇幅和代码块出处：它是从已经查过的页面复制来的索引，长是正常的。库里没有任何术语表、命令或指令时不生成这个文件夹。

## gaps 和 more

`gaps` 读每个话题的 `selection.json`（每一轮的得分、类别、是否选入）和成品页面，写出 `省略报告.md`：

| 档 | 判定 | 通常是什么 |
| --- | --- | --- |
| 高分未选入 | 得分不低于已选入轮次的中位数 | 有术语、命令、流程、决策，只是排在预算外 |
| 一般 | 得分大于零 | 同一件事的反复来回 |
| 无线索 | 得分不大于零 | 寒暄、确认、“继续” |

报告把“缺”分三栏。缺的术语：进了术语候选、原文里解释过或本人问过，而话题文件夹的页面里没有出现。缺的项目内名字：反引号里出现 20 次以上的文件名、字段名、组件名，页面里没有；它们多数不值得进笔记，只在是排查或架构的关键时才补。缺的命令：原文重复 3 次以上，而页面里没有它的第一行。话题还没有页面时这三栏写“未写”。都只是按字面比对，页面里换了说法也会被算作缺，要看一眼再判断。

`more` 从没选入的轮次里按得分再取一份，默认每个话题取第一轮预算的一半；`--keyword` 时改为取提到这个词的轮次，不分档。取过的轮次记为已选入，再运行 `gaps` 数字会相应减少。重新运行 `digest` 会重置这些记录并删掉 `补充N.md`。

## 精读模式（只在用户要求一字不漏时）

| 命令 | 作用 |
| --- | --- |
| `batch <工作区>` | 给选中话题里还没分过批的会话分批 |
| `status <工作区>`、`next <工作区> -n 5` | 进度；接下来要读的批次 |
| `check <工作区> [--batch 批次号]` | 校验抽取卡 |
| `export <工作区>` | 按话题和类型导出卡片 |

用法见 reading_cards.md。工作区里有 `digest/` 时，`verify` 按默认流程检查，不检查卡片的安置；只用精读模式的工作区（没有 `digest/`）才检查 `placement.jsonl`，那些规则见本文件末尾。

## 工作区里有什么

```text
<工作区>/
├── snapshots/s1/        解析后的来源快照
├── catalog.md           会话目录，给模型归话题用
├── topics.json          话题清单，模型写，用户选
├── 话题目录.md           带编号的话题表，给用户看
├── digest/_index.md     每个话题的原文字数和阅读量
├── focus.json           可选：这个人最想留下哪几类内容
├── digest/<话题>/        精选.md、原文资产.md、补充N.md、units.json、selection.json、assets.json
├── 省略报告.md           gaps 写的，补漏时给用户看（`00_跨话题汇总/` 在知识库里，不在工作区）
└── vault_check.json     成品检查报告
```

## 脚本替模型筛掉了什么

这些都不花额度，依据是导出文件自带的结构标记或确定的规则。

| 内容 | 处理 | 依据 |
| --- | --- | --- |
| 用户和 AI 的正文、用户附上的文本文件 | 保留 | 文本块、附件内嵌文本 |
| AI 向用户提的选择题和用户的回答 | 保留 | 工具名含 ask、user_input、question |
| AI 替用户写的文档 | 保留 | 工具输入里有正文，文件是 `.md`、`.txt` 等，或类型是纯文本、Markdown |
| 思考过程 | 去掉 | 块类型 |
| 其他工具调用和工具返回（读文件、搜索、跑命令、改代码、画图） | 去掉 | 块类型 |
| 带 `mapping` 的导出里的工具消息、系统消息、隐藏消息 | 去掉 | 角色或隐藏标记 |
| 前文完整出现过的 300 字以上段落 | 换成一行标记 | 逐字相同；第一次出现完整保留 |
| 超过 4000 字的代码块 | 留开头 1500 字和结尾 500 字 | 长度 |
| 图片、PDF、音视频 | 只登记，不解析 | 文件类型 |

原始导出不会被改动。`start` 加 `--include-tool-blocks` 可以把工具过程读回来。`units.json` 里是没有缩短过的全文，`show` 和 `find` 看到的就是它。

能解析的来源：含 `chat_messages`、`mapping` 或 `messages` 的 JSON，逐行消息的 JSONL，活动记录页面（每条提问一张卡的 HTML，按 45 分钟间隔推断会话），以及 Markdown、文本、普通 HTML。活动记录没有会话边界，推断出的会话可能混着两件事，归话题和写页面时按内容判断。

## topics.json

```json
{"topics": [
  {"name": "芽历", "category": "01_项目", "about": "阳台种植记录应用，从原型到上线", "sessions": ["c001-c020", "c034"], "keep": true},
  {"name": "零散查询", "category": "04_专题知识", "about": "一次性的生活和工具问题", "sessions": ["c021-c033"], "keep": false}
]}
```

- 会话编号来自 `catalog.md`，可以写范围。每段会话归到恰好一个话题。
- `name` 是知识库里的文件夹名，不能重复，不能叫“其他”。`category` 是第一层文件夹。
- `keep` 由用户在节点一的选择决定。
- 没选的话题不会有精选，也不会被写成页面。

`topics` 的报错：`SESSIONS_WITHOUT_TOPIC`（有会话没归话题）、`SESSION_IN_TWO_TOPICS`、`TOPIC_NEEDS_CATEGORY_AND_ABOUT`、`EMPTY_TOPIC`。

## verify 的报错

错误必须修：

| 代码 | 处理 |
| --- | --- |
| `UNMARKED_NONSOURCE_BLOCK` | 代码块不在原文里：换成原文，或在小节标题、代码块前一行写明是模板、改写或示意 |
| `BOOKKEEPING_IN_READER_TEXT` | 正文里出现了 `【u12｜答】`、`[u12]` 这类编号，删掉 |
| `BROKEN_LINK`、`BROKEN_ANCHOR`、`AMBIGUOUS_LINK` | 改链接；同名页面用带路径的写法 |
| `ENTRY_PAGE`、`UNREACHABLE_FROM_ENTRY` | 根目录只留一个 `00_` 入口页；每页都要能从入口两次点击内到达 |
| `PAGE_WITHOUT_NUMBER`、`NUMBERING_NOT_CONTIGUOUS_FROM_00` | 文件夹里的页面从 00 连续编号 |
| `NEEDS_EXACTLY_ONE_H1` | 每页一个一级标题 |

警告逐条看：

| 代码 | 含义 |
| --- | --- |
| `PAGE_TOO_LONG` | 一页超过 6000 字。合并同类项，次要的收进索引表 |
| `TOO_MANY_PAGES`、`TOPIC_TOO_LONG` | 一个话题超过 12 页或 4 万字。减页 |
| `TERMS_NOT_IN_PAGES` | 本人问过并得到解释、且出现在三段以上会话的术语（或原文里提及二十次以上、有解释的常用界面词），话题的页面里一次都没出现。补进术语表，或说明为什么不收 |
| `MATERIAL_WITHOUT_A_PAGE` | 话题的精选和原文资产里明显有某类材料（报告里点名、给出数量），页面里却没有。先判断值不值得留，值得就补进一节或一页；不值得就说明理由。不是页数指标 |
| `PAGE_TOO_THIN`、`PAGES_REPEAT_EACH_OTHER` | 凑页的迹象：一页不到 500 字，或两页三成以上的实质行相同。合并 |
| `TOPIC_NOT_WRITTEN_YET` | 选中的话题还没有页面。中途检查时正常，交付前应当没有 |
| `NO_LEAD_LINE`、`NO_QUICK_LOCATE_TABLE`、`LONG_PARAGRAPH`、`HEADING_DEEPER_THAN_H3`、`PLAIN_PROSE_PAGE` | 版式问题，见 page_specs.md 的对应规则 |

报告的 `topics` 一栏给出每个话题的页数、字数、代码块数、原文字数，以及同等规模话题的常见最少页数（`usual_pages_at_least`：原文五十万字以上 8 页，十万字以上 4 页）。后者只在有材料没处放时才会和警告一起出现，单独看不构成要求。通过检查只说明没有发现这些机械问题，不说明内容有用或正确。

精读模式（工作区没有 `digest/`）另有：`READING_NOT_COMPLETE`、`CARDS_NOT_PLACED`、`PLACEMENT_MISSING`、`PLACEMENT_PAGE_MISSING`、`VERBATIM_NOT_IN_PAGE`、`EXACT_ASSETS_BUT_NO_CODE_BLOCKS`、`OWNER_HAS_NO_PAGES`。`placement.jsonl` 每行一条 JSON：`{"page": "<页面路径>", "cards": ["s1-b0001#1"]}` 记卡片去了哪一页，`{"dropped": [...], "reason": "..."}` 记不收录的卡片和理由。

## 隐私

- 口令、令牌、私钥、验证码不进页面，换成 `<TOKEN>` 这类占位符。原文资产里出现它们时同样处理，不要照抄。
- 默认按本地私有的库处理。要分享给别人时，`verify` 加 `--profile reader-shareable`，并另外去掉姓名、联系方式、可识别的经历。
- 不从对话推断并写下关于健康、心理状况、身份的结论。
- 扫描只做模式匹配，找不出姓名和经历，这些要自己通读。

## 不能运行脚本时

按同样的规则手工做，交付时说明哪些检查是手工做的、范围多大，不要声称脚本通过。

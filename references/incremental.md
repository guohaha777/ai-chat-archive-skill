# 续进新对话，或补整理没选的话题

原则是把新内容融进已有的页面，不另建一套平行的笔记。

## 补整理之前没选的话题

1. 读 `话题目录.md`，用提问工具让用户选要补哪些。
2. 把选中的话题在 `topics.json` 里改成 `"keep": true`，运行 `digest --topic <话题>`（可重复写几个）。
3. 照常读精选、写页面。新话题是新文件夹，已有页面不用动，只需更新入口页。

## 用户带着新的导出回来

1. 对新导出运行 `start`，用同一个工作区。旧会话保留原编号，新会话在 `catalog.md` 里标着“新增”。
2. 把新会话归进 `topics.json`：属于已有话题就加进它的 `sessions`，否则新建话题。新建话题走节点一让用户选。
3. 运行 `topics`，再对有新会话的话题运行 `digest --topic <话题>`。
4. 精选按时间排列，新会话在后面，标题行有日期。只读新增会话的部分，已有页面覆盖过的旧内容不用重读。

## 把新内容写进已有页面

| 情况 | 做法 |
| --- | --- |
| 已有页面有对应小节 | 补进去；是表格就加行 |
| 新内容改变了旧结论或适用条件 | 改写那一节，保留“起初……后来……” |
| 新旧内容条件不同 | 并存，写清各自的条件 |
| 没有合适的位置，内容够多 | 在该话题下新增一页，编号接在后面 |
| 和已有内容重复 | 不写 |

改了一页之后，检查依赖它的地方：话题的总览、术语表、指令与命令页、入口页；最后重新运行 `hub`，跨话题汇总才会跟上。只追加新页面而不更新总览，是最常见的缺陷。

## 保护人工改过的内容

- `verify` 每次通过后会存一份清单 `inventory_last.json`。下次动笔前运行 `python3 scripts/vault_inventory.py <知识库> <工作区>/inventory_now.json --baseline <工作区>/inventory_last.json`，列出用户改过的页面。
- 用户加的段落、改的措辞、手工加的链接原样保留，新内容加在旁边。
- 新证据和用户写的内容矛盾时，不自己判断谁对，在节点三问用户。
- 没有清单时，整页都按人工内容对待。

## 需要先问用户的改动

合并或拆分话题、移动或重命名文件夹、删除有实质内容的页面、给已有页面重新编号。先给出具体方案，用提问工具确认后再做，并在工作区里保存受影响文件的副本。在 Obsidian 之外改名不会自动更新链接，要手动改。

## 知识库不是本 skill 建的

新建工作区，正常处理导出。把现有笔记当成用户写的内容：沿用它的目录和命名，新话题放进合适的现有类别。结构差别很大时不要擅自重组，在节点一给出“沿用现有结构”和“新内容单独放一个类别”两个方案。
